কারণ Context Window যত বড়ই হোক, একসময় সেটা ভরবে। আর বাংলায় ভরবে আরও আগে। এটাই দ্বিতীয় নিয়ম। ▶1 আমরা পেশাদার অনুবাদের ১ হাজার ১২টি ইংরেজি ও বাংলা বাক্য আসল Tokenizer দিয়ে গুনেছি। ▶2 জিপিটি ফোর ও থেকে জিপিটি ফাইভে একই অর্থ প্রকাশ করতে বাংলায় লাগে প্রায় ১ দশমিক ৭১ গুণ Token। ▶3 আর জিপিটি থ্রি পয়েন্ট ফাইভ এবং জিপিটি ফোরের ক্ষেত্রে এই পার্থক্য ছিল ৫ দশমিক ৮৮ গুণ। ▶4 একই কথোপকথন যদি ইংরেজি ও বাংলায় লিখি, তাহলে বাংলার টেবিল আগে ভরে যেতে পারে। আর টেবিল ভরে গেলে কী হয়? কিছু App সবচেয়ে পুরোনো কথাগুলো সরিয়ে দেয়। ▶5 ফলে বাংলায় আপনার প্রথম নির্দেশটাই আগে হারিয়ে যেতে পারে। ▶6 ইংরেজিতেও হারাবে, তবে তুলনামূলকভাবে পরে। ▶7 তাই জরুরি নির্দেশ System Prompt-এ রাখুন। প্রয়োজনে আবার মনে করিয়ে দিন। ▶8 কিছু System পুরোনো কথোপকথনের সারাংশ তৈরি করে রাখে। এই পদ্ধতির নাম Compaction। ▶9 আপনার নিজের ভাষায় Context Window কত দ্রুত ভরে, সেটা মেপে দেখুন।

এবার আসি বাংলায় RAG তৈরি করার সবচেয়ে গুরুত্বপূর্ণ সমস্যায়। আপনি হয়তো ভাবছেন, ইংরেজিতে RAG ভালো কাজ করলে বাংলাতেও করবে। সব সময় না। ▶1 ২০২৬ সালে North South University-র গবেষকেরা বাংলাদেশের সরকারি কৃষি প্রকাশনার ২৮৪টি Document দিয়ে RAG পরীক্ষা করেছেন। গবেষণাটি এখনো Preprint। ফলাফলটা খুবই গুরুত্বপূর্ণ। ▶2 বইয়ের ভাষায় প্রশ্ন করলে সঠিক তথ্য খুঁজে পাওয়ার হার ছিল প্রায় ৯৭ শতাংশ। ▶3 কিন্তু কৃষকের নিজের ভাষায় প্রশ্ন করলে তা নেমে আসে মাত্র ৯ শতাংশে। কেন? ▶4 কারণ কৃষক হয়তো প্রশ্ন করছেন, ধানের পাতায় বাদামি দাগ পড়েছে, কী করব? কিন্তু Document-এ রোগের বৈজ্ঞানিক নাম লেখা। দুটোর অর্থ কাছাকাছি, কিন্তু শব্দ আলাদা। ▶5 এই পরীক্ষায় BM25 প্রায় ৫২ শতাংশ ফল দিয়েছে। আর Semantic Search ও Keyword Search একসঙ্গে ব্যবহার করলে আরও ভালো ফল পাওয়া গেছে। ▶6 অন্যদিকে, ইংরেজি প্রশ্ন দিয়ে বাংলা Document খুঁজলে Keyword Search প্রায় শূন্য ফল দিয়েছে। এটাই নবম নিয়ম। আপনার User যেভাবে প্রশ্ন করে, ঠিক সেভাবে RAG পরীক্ষা করুন। শুধু বইয়ের ভাষায় নয়, মানুষের বাস্তব ভাষায়।

তাহলে আজকের নয়টি নিয়ম আবার মনে করি। ▶1 এক। নতুন বিষয় হলে নতুন Chat। ▶2 দুই। বাংলায় Token আগে শেষ হতে পারে। ▶3 তিন। জরুরি তথ্য শুরুতে বা শেষে রাখুন। ▶4 চার। নিজের Data দিয়ে কাজের Context Window মাপুন। ▶5 পাঁচ। বড় Context মানে বড় বিল ও বেশি অপেক্ষা। ▶6 ছয়। Document ছোট হলে পুরোটা, বড় হলে RAG। ▶7 সাত। Chunk ছোট রাখুন, সঙ্গে Context দিন। ▶8 আট। Semantic Search ও Keyword Search একসঙ্গে ব্যবহার করুন। ▶9 নয়। User যেভাবে প্রশ্ন করে, সেভাবে Test করুন। ▶10 শেষে একটা কথা মনে রাখবেন। AI-এর সামনে যত বেশি তথ্য রাখবেন, তত বেশি খরচ, তত বেশি অপেক্ষা, আর ভুলের সুযোগও তত বেশি। তাই কম রাখুন, ঠিক রাখুন, আর জরুরিটা রাখুন শুরুতে বা শেষে।
