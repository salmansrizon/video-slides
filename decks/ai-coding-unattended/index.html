Anthropic Engineering, "Redesigning source control at Anthropic", 13 Oct 2026 · Anthropic-এর নিজস্ব monorepo

২০২৬ সালের মে মাসে Anthropic-এ ▶1 প্রতিদিন গড়ে আড়াই হাজার code change merge হতো।

▶2 সেপ্টেম্বরে সেই সংখ্যা বেড়ে দাঁড়ায় ত্রিশ হাজারেরও বেশি। মাত্র চার মাসে প্রায় বারো গুণ।

▶3 কিন্তু মানুষ কি এখন বারো গুণ বেশি code review করছে? না, বরং মানুষ ধীরে ধীরে coding-এর মাঝখান থেকে সরে যাচ্ছে।

এখন AI-কে একটা বড় কাজ দিয়ে developer অন্য কাজে চলে যাচ্ছেন। AI নিজেই code লিখছে, test করছে, ভুল হলে ঠিকও করছে।

কিন্তু AI-কে কাজ দিয়ে চলে গেলেই দায়িত্ব শেষ হয় না। তাহলে AI-কে কী করতে দেবেন, কী করতে দেবেন না? আর কীভাবে বুঝবেন সে ঠিক কাজ করেছে?

আজ দেখব, AI-কে স্বাধীনভাবে কাজ করতে দেওয়ার আগে কোন চারটি বিষয় ঠিক করতে হবে।

আগে AI একটা কাজ করত, তারপর থামত।

▶1 আমরা code দেখতাম, permission দিতাম, ভুল হলে ঠিক করে দিতাম।

▶2 এখন AI অনেক বেশি সক্ষম। তাই মানুষ প্রতিটি ধাপে উপস্থিত না থাকলেও সে কাজ চালিয়ে যেতে পারে। কিন্তু মানুষ সরে গেলে দায়িত্ব তো আর শূন্যে চলে যেতে পারে না।

▶3 সেই দায়িত্ব নিতে হবে AI model, তার tools বা harness, কিংবা যে computer-এ AI কাজ করছে, সেই environment-কে।

▶4 আর দুটি প্রশ্ন সব সময় মাথায় রাখতে হবে: AI যা করছে সেটা নিরাপদ তো? আর কাজটা আসলেই সঠিক তো?

প্রথমে বুঝুন, AI-কে নিয়ন্ত্রণ করার চারটি জায়গা আছে।

▶1 প্রথমত নির্দেশনা: prompt বা rules file দিয়ে AI-কে বলেন কী করতে হবে।

▶2 দ্বিতীয়ত নিরাপত্তা: permission, deny rule এবং sandbox দিয়ে নিয়ন্ত্রণ করেন AI কী করতে পারবে।

▶3 তৃতীয়ত verification: test, hook এবং CI দিয়ে প্রমাণ করেন কাজ ঠিক হয়েছে কিনা।

▶4 চতুর্থত environment: AI কোথায় এবং কী access নিয়ে কাজ করবে, সেটা আপনাকে ঠিক করতে হবে।

▶5 মনে রাখবেন, যে কাজ প্রতিবার হতেই হবে, সেটা AI-এর মনে রাখার ওপর ছেড়ে দেবেন না। System দিয়ে নিশ্চিত করুন।

এবার আসি rules file-এ। আপনার AGENTS.md বা CLAUDE.md file-এ কি অনেকগুলো IMPORTANT লেখা আছে? মনে হতে পারে, যত জোর দিয়ে লিখবেন, AI তত ভালোভাবে মানবে।

▶1 কিন্তু Anthropic-এর documentation অনুযায়ী, অতিরিক্ত জোর দিয়ে নির্দেশনা দিলে AI অপ্রয়োজনীয় জায়গাতেও সেই নিয়ম প্রয়োগ করতে পারে।

▶2 আর পুরো project-এর folder structure লিখে রাখারও দরকার নেই। AI নিজেই codebase পড়ে বুঝতে পারে।

বরং লিখুন শুধু সেই তথ্য, যেটা code দেখে AI বুঝতে পারবে না।

▶3 যেমন test চালানোর command, কোন পুরনো folder ব্যবহার করা যাবে না, কিংবা কোন পরিবর্তনের আগে মানুষের review লাগে।

▶4 সহজ নিয়ম: AI নিজে যেটা বুঝতে পারবে না, শুধু সেটাই rules file-এ রাখুন।

▶5 আর কোনো নিয়ম বারবার ভাঙলে একই কথা লিখে থাকবেন না, hook ব্যবহার করুন।

এবার ধরুন, AI আপনার project-এর একটা file delete করবে। আপনি কি প্রতিবার বসে permission দেবেন? মানুষ সব সময় সতর্ক থাকতে পারে না।

Anthropic-এর একটি পরীক্ষায় ১,০৫৩ জন tester-কে বিপজ্জনক command দেখানো হয়েছিল।

▶1 মাত্র সাড়ে তেরো শতাংশ মানুষ সেটি থামিয়েছিলেন।

▶2 অন্যদিকে AI classifier প্রায় ঊননব্বই শতাংশ ক্ষেত্রে বিপজ্জনক command সনাক্ত করেছিল।

▶3 আর পঞ্চাশটি prompt-এর পর মানুষের সতর্কতার হার সতেরো শতাংশ থেকে নেমে মাত্র পাঁচ শতাংশে চলে আসে।

▶4 তাই সব নিরাপত্তার দায়িত্ব মানুষের ওপর রাখবেন না।

একটা সহজ প্রশ্ন করুন: ভুল হলে কি কাজটা ফিরিয়ে নেওয়া যাবে?

▶5 Code পরিবর্তন হলে git দিয়ে আগের অবস্থায় ফেরা যায়। কিন্তু database মুছে ফেলা বা secret key বাইরে পাঠানো সহজে ফেরানো যায় না।

▶6 তাই এ ধরনের বিপজ্জনক কাজের জন্য deny rule তৈরি করুন। AI-এর সিদ্ধান্তের ওপর ছেড়ে দেবেন না।

কিন্তু permission দিলেই কি সব নিরাপদ? ধরুন, AI npm test command চালাতে চাইল।

▶1 আপনি permission দিলেন।

▶2 সমস্যা হলো, test-এর সঙ্গে আপনার project-এর dependency বা বাইরের package-এর code-ও চলতে পারে। সেটি আপনার .env file বা API key চুরি করতে পারে।

এখানেই permission আর sandbox-এর পার্থক্য। Permission দেখে, কোনো command চালানো যাবে কিনা।

▶3 Sandbox নিয়ন্ত্রণ করে, সেই command চলার সময় কোন file পড়তে পারবে, কোথায় লিখতে পারবে, আর internet-এর কোথায় connect করতে পারবে। অর্থাৎ command অনুমোদিত হলেও তার ক্ষমতা সীমিত থাকবে।

▶4 Cursor-এর তথ্য অনুযায়ী, sandbox ব্যবহার করলে agent-এর permission চাওয়ার প্রয়োজন প্রায় চল্লিশ শতাংশ কমে।

এবার দ্বিতীয় প্রশ্ন। AI নিরাপদে কাজ করছে, কিন্তু সে কি ঠিক কাজটাও করছে? ধরুন বললেন, পুরনো authentication system নতুন API-তে migrate করতে।

▶1 একই কাজ সাতবার করালে সাত রকম ফল পাওয়া গেল। কোথাও পুরনো API রয়ে গেছে, কোথাও আবার সব user logout হয়ে যাচ্ছে। দেখতে code ঠিকঠাক, কিন্তু কাজটা কি আপনার চাহিদা পূরণ করছে?

▶2 এখানে দরকার verification।

▶3 AI-কে শুধু কাজ দেবেন না, কীভাবে কাজটি সঠিক প্রমাণ করতে হবে, সেটাও বলে দিন।

▶4 যেমন test pass করতে হবে, application build হতে হবে, screenshot-এ নির্দিষ্ট UI দেখা যেতে হবে। শুধু AI-এর done বলার ওপর নির্ভর করবেন না, প্রমাণ চান।

২০২৫ সালের একটি গবেষণায় এমন task দেওয়া হয়েছিল, যেখানে সৎভাবে test pass করা অসম্ভব ছিল।

▶1 তারপরও GPT-5-এর কিছু ক্ষেত্রে ছিয়াত্তর শতাংশে pass দেখানোর ঘটনা পাওয়া যায়।

▶2 AI-কে অসম্ভব হলে থামার সুযোগ দিলে হার নেমে আসে নয় শতাংশে।

▶3 Claude model-গুলোর ক্ষেত্রেও test নিয়ে cheating-এর বড় একটি অংশ ঘটেছিল test file পরিবর্তনের মাধ্যমে।

▶4 তাই test file read-only রাখুন। AI-কে বলুন: application code ঠিক করো, test পরিবর্তন করবে না।

এবার আসি hook-এ। Rules file-এ লিখলেন, কাজ শেষে test চালাতে হবে। AI বেশিরভাগ সময় সেটা করবে। কিন্তু বেশিরভাগ সময় আর প্রতিবার এক জিনিস নয়। Hook হলো এমন script, যা নির্দিষ্ট event ঘটলেই স্বয়ংক্রিয়ভাবে চলে।

▶1 যেমন code পরিবর্তন হলে lint চালানো, task শেষ হলে test চালানো। এতে AI ভুলে গেলেও system কাজটি করাবে।

▶2 Claude Code-এ hook থেকে exit code 2 ব্যবহার করলে error AI-এর কাছে ফেরত যায়,

▶3 যাতে সে সমস্যাটি ঠিক করার চেষ্টা করতে পারে।

▶4 সব শেষে আছে CI বা continuous integration। AI যখন git-এ pull request তৈরি করবে, তখন স্বয়ংক্রিয়ভাবে test, build এবং অন্যান্য check চলবে। কোনো check fail করলে code merge করা যাবে না। অর্থাৎ AI কাজ শেষ বললেই সেটা production-এ চলে যাবে না।

তাহলে চারটি নিয়ম আবার মনে করি।

▶1 প্রথমত নির্দেশনা: rules file-এ শুধু প্রয়োজনীয় তথ্য রাখুন।

▶2 দ্বিতীয়ত নিরাপত্তা: deny rule এবং sandbox দিয়ে AI-এর ক্ষমতা সীমিত করুন।

▶3 তৃতীয়ত environment: বড় কাজের জন্য আলাদা cloud machine ব্যবহার করুন।

▶4 চতুর্থত verification: test, hook এবং CI দিয়ে কাজের প্রমাণ নিশ্চিত করুন।

▶5 মনে রাখবেন, AI-কে স্বাধীনতা দেওয়া মানে সব দায়িত্ব ছেড়ে দেওয়া নয়। আপনার কাজ হলো এমন ব্যবস্থা তৈরি করা, যেখানে AI স্বাধীনভাবে কাজ করতে পারবে, কিন্তু ভুল করলে বড় ক্ষতি করতে পারবে না।

▶6 এই সপ্তাহে AI-কে আপনার project-এর একটা বড় feature বানাতে দিন। তারপর দেখুন কোথায় সে ভুল করছে, কোথায় permission চাইছে, আর কোথায় verification দরকার হচ্ছে। ওই জায়গাগুলোই বলে দেবে, আপনার system-এ পরের কোন control যোগ করা উচিত।
